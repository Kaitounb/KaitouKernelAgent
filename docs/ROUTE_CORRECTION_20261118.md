# 2026-11-18 路线与已有工作更正

当前依据：用户要求主要借鉴 PyTorch KernelAgent、NVIDIA KDA、OpenBMB ForgeKernel、KernelBench、FlashInfer-Bench，尽量减少自行设计；kernel 尽量使用 CUDA C++。

## 统一实施规则

1. 五个项目是工程实施的主要来源，采用分工见 [UPSTREAM_REUSE.md](../provenance/UPSTREAM_REUSE.md)，固定版本见 [upstream-lock.json](../provenance/upstream-lock.json)。先使用原接口／模块，必要时提取适配，已证实的缺口才新增实现。
2. CUDA 优先针对计算 kernel。成熟项目的 Python 构建、评测、计时与控制层可以保留；不再将“验证／计时必须优先 C++”作为架构约束。
3. 不再预设自行搭建整套状态机、worker、benchmark、FFI 或动态加载器。每次实现先写上游文件／符号、保留内容、必要改动和验证方式。
4. 教学小例子用于理解公式、线程、地址、同步，优先从可核实来源学习／简化。工程基线优先适配成熟 CUDA 实现，不以整套教学代码重写成生产框架为目标。
5. FlashAttention、FlashMLA、DeepGEMM 是后续算子的优先来源；具体文件、精度与目标卡支持在对应阶段确认。
