# Shared memory：一个 16×16 块怎样算完 K=17

沿用 KernelBench commit `423217d9fda91e0c2d67e4a43bf62f96f6d104f1` 的 `src/kernelbench/prompts/few_shot/model_new_ex_tiled_matmul.py`。运行原文件的 `ModelNew` → `load_inline` → `tiled_matmul_cuda` → `tiled_matmul_kernel`，保留 CUDA 计算、装载和同步逻辑。新增内容只在现有正确性脚本里，用固定输入检查 K=15 到 K=16 的交界。读源码时可打开 [带中文注释的 CUDA 视图](tiled_matmul_reading.cu)。

## 一个线程同时负责输出和搬运

以行优先的 A[2,17]、B[17,2] 为例。网格只有一个块，块内有 16×16 个线程。写作 `(x,y)` 的线程负责输出 `C[y,x]`，仅当 `y<2 && x<2` 时写入。每轮的起始 K 下标 `s` 依次取 0、16。所有线程分别填一个 A 和一个 B 的 shared 槽位，越界填 0。

| shared 槽 | 全局坐标 | FP32 全局元素下标 | 有效条件 |
|---|---|---|---|
| `M_tile[y][x]` | `A[y,s+x]` | `17*y+s+x` | `y<2 && s+x<17` |
| `N_tile[y][x]` | `B[s+y,x]` | `2*(s+y)+x` | `s+y<17 && x<2` |

字节偏移为元素下标乘 4。第一轮中，线程 `(15,1)` 的输出列越界，它仍要搬运 `A[1,15]`，全局下标 32。两个有效输出 `C[1,0]`、`C[1,1]` 都要读它搬来的 `M_tile[1][15]`。同理，输出行越界的线程 `(1,15)` 搬运 `B[15,1]`，全局下标 31，供 `C[0,1]`、`C[1,1]` 使用。此例每个有用的 A 或 B 元素供两个有效输出消费，满 16×16 输出块内则各供 16 个输出消费。

按源码的有效全局读取计数，第一轮读 `2×16 + 16×2 = 64` 个元素，第二轮读 `2×1 + 1×2 = 4` 个。若每个输出线程独立从全局读取所有点积项，则会发出 `4×17×2 = 136` 次逻辑元素读取。这个计数未计入缓存、访存合并或 shared 中填零和读写的成本。

## 两次同步分别等什么

1. 所有线程填好两张 shared tile 后，在第一次 `__syncthreads()` 汇合。计算 `C[1,1]` 的线程可以读到其他线程写入的 A、B 元素。
2. 每个线程沿本地 K 偏移 `i=0..15` 计算 `M_tile[y][i] * N_tile[i][x]`，加到自己的 `res`。第二次 `__syncthreads()` 等大家读完，下一轮才可覆盖同一片 shared memory。

输出坐标越界的线程同样装载或填零，并通过两个屏障。边界判断分别用于 A 装载、B 装载和 C 写回。若把 C 的边界判断改成开头提前退出，会丢掉上面两个线程的搬运。第二轮只有 K=16 有效，其他 K 槽显式写 0，防止第一轮的非零值残留。[CUDA Programming Guide](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html#shared-memory)

## 固定输入与手算

只在 K=0、15、16 放非零值，其余置零。A 的两行在这三个位置分别为 `[1,2,3]`、`[4,5,6]`，B 的对应三行为 `[7,8]`、`[9,10]`、`[11,12]`。

第一轮贡献 `[[25,28],[73,82]]`，第二轮贡献 `[[33,36],[66,72]]`。例如 `C[0,0]=(1×7+2×9)+3×11=58`。预期总输出为 `[[58,64],[139,154]]`。

验证保留相同的 2×2×17 形状。分别运行完整输入、K=16 置零的输入、K<16 置零的输入；每组调用两次，独立核对手算期望、CPU FP64 参考和 A/B 不变。两组分段结果来自独立调用，可用于核对两段的贡献。
